# Crop-классификация, YOLOv8 и подсчет животных

Фраза:

> На текущем этапе реализована и сравнена классификация по crop-изображениям животных; детекция YOLOv8 нужна для следующей части - подсчета животных в полном кадре.

Ниже - подробное объяснение с нуля.

## 1. Что вообще решает проект

Есть изображения с животными: коровы и овцы.

Задача проекта состоит из двух разных частей:

1. **Классификация**  
   Ответить на вопрос:  
   **"Что изображено на этом фрагменте: корова или овца?"**

2. **Детекция и подсчет**  
   Ответить на вопросы:  
   **"Где на полном изображении находятся животные?"**  
   **"Сколько их?"**  
   **"Сколько коров и сколько овец?"**

Это похожие задачи, но технически они разные.

## 2. Что такое crop-изображение

`Crop` - это вырезанный фрагмент изображения.

Например, есть полный кадр с дрона:

```text
[ поле, дорога, трава, 20 животных, деревья ]
```

На таком изображении животные занимают только маленькую часть кадра.

Если у нас есть bounding box вокруг одного животного, мы можем вырезать только его:

```text
[ одно животное ]
```

Вот это и есть `crop`.

То есть:

```text
полное изображение -> bounding box -> вырезанный crop животного
```

## 3. Что делает классификатор

Классификатор получает уже готовый crop.

Например:

```text
вход:  картинка с одним животным
выход: cattle или sheep
```

То есть модель не ищет животное на изображении. Она предполагает, что животное уже найдено и вырезано.

Пример:

```text
crop_001.jpg -> cattle
crop_002.jpg -> sheep
crop_003.jpg -> cattle
```

В проекте именно это уже сделано:

- были взяты изображения из WAID и COCO;
- по bounding boxes вырезаны животные;
- получено `51 320` crop-изображений;
- обучены модели:
  - Custom CNN;
  - ResNet50;
  - VGG16;
  - MobileNetV2;
- модели сравнили по accuracy, precision, recall, F1.

Лучший результат классификации:

```text
VGG16 accuracy = 0.9738
Custom CNN accuracy = 0.9610
ResNet50 accuracy = 0.9570
MobileNetV2 accuracy = 0.9498
```

## 4. Почему классификация не равна подсчету

Очень важный момент.

Классификация отвечает только:

```text
Это корова или овца?
```

Но она не отвечает:

```text
Где животные на полном кадре?
Сколько животных на полном кадре?
```

Потому что классификатор видит уже вырезанный объект.

Например, если дать классификатору crop:

```text
[ овца ]
```

он скажет:

```text
sheep
```

Но если дать ему полный дроновый кадр:

```text
[ поле + 30 маленьких животных ]
```

классификатор не умеет сам найти все 30 животных. Он может только попытаться классифицировать всю картинку целиком, но это будет неправильная постановка задачи.

## 5. Что такое детекция

Детекция - это задача поиска объектов на полном изображении.

Детектор получает полный кадр:

```text
[ поле, трава, 10 коров, 15 овец ]
```

И возвращает:

```text
животное 1: cattle, координаты box
животное 2: sheep, координаты box
животное 3: sheep, координаты box
...
```

То есть detector делает две вещи сразу:

1. Находит, **где** объект.
2. Определяет, **какой это класс**.

Формат ответа примерно такой:

```text
class = cattle
confidence = 0.91
box = [x1, y1, x2, y2]
```

## 6. Что такое YOLOv8

YOLOv8 - это современная модель object detection.

YOLO расшифровывается как:

```text
You Only Look Once
```

Идея: модель смотрит на изображение один раз и сразу предсказывает все объекты.

Для проекта YOLOv8 нужна так:

```text
полный кадр -> YOLOv8 -> bounding boxes cattle/sheep -> count
```

Например:

```text
YOLO нашла:
- 8 cattle boxes
- 13 sheep boxes

итог:
cattle count = 8
sheep count = 13
total count = 21
```

## 7. Почему YOLOv8 нужна именно для подсчета

Чтобы посчитать животных, нужно сначала их найти.

Если модель нашла 20 bounding boxes, значит она считает, что на изображении 20 объектов.

Пример:

```text
ground truth:
на изображении 12 животных

YOLO prediction:
нашла 11 животных

ошибка counting:
|12 - 11| = 1
```

Поэтому counting строится поверх detection.

Схема:

```text
image
  ↓
YOLOv8 detects boxes
  ↓
count boxes
  ↓
compare predicted count with true count
```

## 8. Главное различие: classification vs detection

| Вопрос | Classification | Detection |
|---|---|---|
| Что получает модель? | Crop одного животного | Полное изображение |
| Что возвращает модель? | Класс: cattle/sheep | Boxes + классы + confidence |
| Умеет ли искать животное? | Нет | Да |
| Умеет ли считать животных? | Нет напрямую | Да, через количество boxes |
| Метрики | accuracy, precision, recall, F1 | mAP, MAE, R² |

## 9. Как это объяснить на защите

Можно сказать так:

> На текущем этапе я решила задачу классификации: если животное уже найдено и вырезано из изображения, модель определяет, корова это или овца. Для этого я подготовила 51 320 crop-изображений и сравнила Custom CNN, ResNet50, VGG16 и MobileNetV2. Однако классификация не решает задачу подсчета, потому что она не ищет объекты на полном кадре. Для подсчета нужна детекция: YOLOv8 должна найти все bounding boxes животных на полном изображении, после чего количество найденных boxes можно использовать как predicted count.

English version:

> At the current stage, I solved the crop-based classification task: given an already localized animal crop, the model predicts whether it is cattle or sheep. However, classification does not solve counting, because it does not locate animals in a full image. For counting, I need object detection with YOLOv8: it detects all animal bounding boxes in the full image, and the number of detected boxes becomes the predicted count.

## 10. Простой пример

Допустим, есть полное изображение:

```text
image_01.jpg
```

На нем:

```text
3 коровы
2 овцы
```

### Classification pipeline

Сначала кто-то уже должен вырезать животных:

```text
crop_1.jpg -> cattle
crop_2.jpg -> cattle
crop_3.jpg -> cattle
crop_4.jpg -> sheep
crop_5.jpg -> sheep
```

Классификатор работает только с этими crops.

### Detection/counting pipeline

YOLOv8 получает сразу полное изображение:

```text
image_01.jpg
```

И сама выдает:

```text
box 1 -> cattle
box 2 -> cattle
box 3 -> cattle
box 4 -> sheep
box 5 -> sheep
```

После этого:

```text
cattle count = 3
sheep count = 2
total count = 5
```

Вот почему для counting нужен YOLOv8.

## 11. Что важно не перепутать

Нельзя говорить:

> Классификатор считает животных.

Правильно говорить:

> Классификатор определяет класс уже найденного животного. Для подсчета в полном кадре нужна detector-модель, например YOLOv8.

Нельзя говорить:

> YOLOv8 уже показала такие-то результаты.

Если Notebook 06 еще не реализован, правильно:

> YOLOv8 запланирована для следующего этапа. Ее качество нужно будет оценить через detection metrics, например mAP, и counting metrics, например MAE и R².

## 12. Очень коротко

Классификация:

```text
одно вырезанное животное -> cattle или sheep
```

Детекция:

```text
полное изображение -> где все животные и какого они класса
```

Подсчет:

```text
количество найденных YOLO boxes -> predicted count
```

Поэтому:

```text
crop classification уже сделана;
YOLOv8 detection нужна для counting.
```
