# Зачем нужны train, validation и test

`train / validation / test` нужны, чтобы честно обучить модель, выбрать лучшую и проверить, как она будет работать на новых данных.

Коротко:

```text
train       -> учим модель
validation  -> выбираем лучшую модель / настройки
test        -> финальная честная проверка
```

## 1. Train set

`Train` - это данные, на которых модель учится.

Например, у нас есть данные о домах:

```text
LotArea, YearBuilt, OverallCond -> SalePrice
```

Модель смотрит на много таких примеров и пытается найти закономерности:

```text
больше площадь -> выше цена
новее дом -> выше цена
лучшее состояние -> выше цена
```

То есть:

```text
train = учебник для модели
```

## 2. Validation set

`Validation` нужен, чтобы выбрать, какая модель лучше.

Например, мы обучили несколько моделей:

```text
Linear Regression
Random Forest
SVR
Ridge
```

Все они учились на `train`.

Потом мы проверяем их на `validation`:

```text
Linear Regression -> MAPE 0.19
Random Forest     -> MAPE 0.14
SVR               -> MAPE 0.18
Ridge             -> MAPE 0.17
```

Если меньше ошибка, модель лучше.

Значит, по validation мы выбираем:

```text
best model = Random Forest
```

То есть:

```text
validation = экзамен для выбора модели
```

## 3. Test set

`Test` нужен для финальной честной проверки.

После того как мы уже выбрали лучшую модель по validation, мы один раз проверяем ее на test.

Почему test нельзя использовать раньше?

Потому что если мы много раз смотрим на test и подбираем модель под него, test перестает быть честной проверкой. Мы как будто заранее подсмотрели ответы.

То есть:

```text
test = финальный независимый экзамен
```

## 4. Простая аналогия

Представь подготовку к экзамену.

```text
train       = учебник и домашние задания
validation  = пробный экзамен
test        = настоящий экзамен
```

Если ты готовишься по учебнику - это нормально.

Если ты используешь пробный экзамен, чтобы понять слабые места - это нормально.

Но если ты заранее знаешь вопросы настоящего экзамена и подстраиваешься под них, результат уже нечестный.

То же самое в ML.

## 5. Почему нельзя использовать только train и test

Можно сделать так:

```text
train -> учим
test  -> проверяем
```

Но тогда возникает проблема.

Допустим, мы пробуем 10 разных моделей и каждый раз смотрим на test:

```text
model 1 -> test error 0.20
model 2 -> test error 0.18
model 3 -> test error 0.16
...
```

Мы начинаем выбирать модель по test.

Тогда test фактически превращается в validation.

И у нас больше нет независимой финальной проверки.

Поэтому лучше:

```text
train -> учим
validation -> выбираем
test -> финально проверяем
```

## 6. В house price prediction

В задаче предсказания цены дома:

```text
X = признаки дома
y = SalePrice
```

Например:

```text
X:
LotArea
YearBuilt
TotalBsmtSF
OverallCond
BldgType
MSZoning

y:
SalePrice
```

Мы делим данные:

```text
train       60%
validation 20%
test        20%
```

На `train` модель учится.

На `validation` мы выбираем лучшую модель:

```text
SVR или RandomForest или LinearRegression
```

На `test` мы проверяем финальное качество выбранной модели.

## 7. Что будет, если не делать validation

Если нет validation, есть риск выбрать модель, которая случайно хорошо показала себя на test.

Это называется переобучение на test set.

Формально модель не обучалась на test, но человек много раз смотрел на test и принимал решения по нему. Это тоже утечка информации.

## 8. Что такое data leakage

`Data leakage` - это когда информация из validation/test случайно попадает в обучение.

Пример плохого подхода:

```text
1. Взять весь dataset
2. Заполнить пропуски средним по всему dataset
3. Сделать OneHotEncoder по всему dataset
4. Потом разделить на train/test
```

Почему плохо?

Потому что при заполнении пропусков и encoding мы уже использовали информацию из test.

Правильнее:

```text
1. Сначала разделить на train/validation/test
2. На train обучить imputer и encoder
3. Применить их к validation/test
```

Именно поэтому во втором notebook используется:

```text
Pipeline
ColumnTransformer
```

Они помогают сделать preprocessing правильно.

## 9. Очень коротко для защиты

Можно сказать так:

> Train нужен, чтобы обучить модель. Validation нужен, чтобы выбрать лучшую модель и настройки, не трогая финальный test. Test нужен для честной финальной оценки на данных, которые модель и процесс выбора модели раньше не видели.

English version:

> The train set is used to fit the model. The validation set is used to compare models and tune decisions. The test set is kept untouched until the end, so it gives an unbiased final estimate of performance on unseen data.
